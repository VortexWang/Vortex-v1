# 需求变更申请

按需求 0.3 节，冻结后的修改须记录版本号、变更原因、影响的需求编号与验收项，并重新评审。

## CR-01 引擎接口 `DrainUsage` 的返回类型

| 项 | 内容 |
| --- | --- |
| 提出日期 | 2026-10-31 |
| 来源 | 实现 ENG-T01（引擎骨架）时发现 |
| 现状 | 需求 8.2 节代码块：`DrainUsage() []UsageDelta` |
| 问题 | 已锁定的契约 C2a（决定 D8）规定引擎输出为 `runtime.v1.UsageSnapshot`，除逐规则用量外还必须携带 LIM-009 的需求信号（令牌耗尽占比）与逐授权消费量（计费授权结算依据）。`[]UsageDelta` 无法承载后两者，需求与契约不一致 |
| 建议 | 8.2 节改为 `DrainUsage() UsageSnapshot // Agent 每秒拉取：用量、需求信号、授权消费` |
| 影响的需求 | 8.2 节、ENG-039、LIM-009 |
| 影响的验收项 | 无（不改变任何行为，只修正接口签名） |
| 当前处理 | 代码按契约实现（`engine/engine.go` 注释中已标注），变更评审通过后作为需求 V1.8 发布 |

## CR-02 Edge Hub 实例证书有效期与续签

| 项 | 内容 |
| --- | --- |
| 提出日期 | 2026-11-01 |
| 来源 | M3 实现实例引导（HUB-T19）时发现契约缺口；随 C2 变更 CC-02 评审 |
| 现状 | AGT-012 与附录 A 只规定节点证书（30 天，剩余 1/3 续签）；SEC-012 规定中间 CA 签发“节点与组件证书”，但没有组件（Edge Hub）证书的有效期与续签 |
| 问题 | 实例证书没有续签途径时，到期即导致区域停止转发（节点拒绝过期的 Edge Hub 证书，运行授权 5 分钟内到期） |
| 建议 | 附录 A 增加一行：“Edge Hub 实例证书有效期 / 续签点：30 天 / 剩余 1/3；经 HubControl.RenewHubCert 续签，私钥在本地重新生成；续签失败告警并退避重试”；HUB-T19 的描述中“证书续签”指向该接口 |
| 影响的需求 | SEC-012、附录 A、HUB-T19（开发方案 03） |
| 影响的验收项 | 无新增指标；实例证书续签纳入 M4 的后端签发验收 |
| 当前处理 | 2026-11-01 评审批准；Edge Hub 侧已实现（`edge-hub/app/cert.go`），后端签发在 M4 实现；作为需求 V1.8 发布 |
