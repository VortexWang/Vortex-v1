端到端测试发现一处设计错误并已修正：Edge Hub 起初要求同一启动的计量批次序号连续，缺批不确认。但切换实例前已被原实例确认的批次不会重发，新实例看到的序号天然有缺口，导致之后的批次永远不被确认。改为按 (node, boot, seq) 逐个去重、不要求连续；累计确认仍成立，因为 Agent 在一条流上总是按序号递增发送全部未确认批次。

第七批的端到端测试又发现两处问题并已修正：① 节点切换实例后重启，新实例从未给它推送过份额（份额原先只在节点首次 Prepare 时由后端推送），租户限速为 0、无法转发。改为 Edge Hub 在节点接入时上报在线状态，后端据此为每个新启动推送份额。② 已上报条目全部被确认后，其后的本地专用条目永远显示为“未确认”。改为在这种情况下本地推进确认位置。

第八批的随机测试发现一处原有缺陷并已修正：节点首次接入时，签发器只在内存中记下它的启动 ID，没有写账本。如果之后还没签发任何授权 Edge Hub 就重启了，就认不出该节点的下一次新启动，LIM-010 转移会被漏掉。现在首次接入也写账本。

故障注入的变异检查：断线即停止转发、自治到期仍续期、探测结果不进入选路，这 3 项都被故障测试发现。另有两项单独做时不会被发现，因为每项都有另一道检查兜底：去掉签发时的 available 上限，额度账户仍会拒绝超额预留；去掉额度账户的检查，签发时的上限仍然生效。两道同时去掉后测试立即失败（issued 达到委托额度的 9 倍）。还有一项（对账在 STARTED 之前就上报）在端到端中无法观察，因为模拟后端总是先下发限制再发 STARTED；这一项由 upstream 单元测试覆盖。

第十批变异检查 8 项全部被发现（Edge Hub 证书 URI 校验、链校验、吊销、Commit 动作判定、引擎错误判定等），其中链校验与 Commit 动作判定是补测试后被发现的；服务端“要求已校验的证书链”一项与握手层校验重复（提供证书就必须通过校验），属于纵深防御，无法单独观察。

第十一批变异检查 7 项全部被发现（规则信息写账本、规则并集、后端证书身份、吊销判定、期望配置版本等，其中后两项是补测试后被发现的）。全栈测试发现一处部署要求：Edge Hub 证书同时用作后端的客户端证书，扩展用途须含 clientAuth（已写入契约补充 L5）。

第十二批变异检查 11 项全部被发现（签发结果的公钥 / 节点 ID 校验、过期不出示证书、续签阈值、key.prev 恢复、续签后替换证书、自治时拒绝注册、私钥文件权限、响应 node_id 与证书一致性等；后两项补测试后被发现）。

第十三批变异检查 8 项全部被发现（引擎采用当前身份、他节点身份不采用、组装时配置 Tunnel、续签后取当前证书、链路监听、探测结果进入选路、证书节点 ID 一致性、Agent 使用传入的启动）；其中后 5 项是补单元测试后被发现的。

第十四批变异检查 12 项中 10 项被发现（偏差估计、扣除不确定度、取绝对值、本地回退、连接建立时比对、告警判定、记录结果、status 告警字段、取响应头中的时间、Edge Hub 可注入时钟）；2 项为等价变异，已简化代码：去掉单调读数（Edge Hub 时刻本身不带单调读数，相减已按墙钟进行）、发送时刻取 Connect 返回时还是构造连接时（相差微秒）。

契约缺口（需要变更评审）：HubControl 只有 `EnrollHub`，没有 Edge Hub 实例证书的续签 RPC；实例证书到期前只能重新引导。建议新增 `RenewHubCert(RenewHubCertRequest{csr_der}) returns (RenewHubCertResponse{certificate_chain_der})`，身份取自当前 mTLS 证书。
