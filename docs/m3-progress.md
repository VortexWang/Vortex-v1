## 外部依赖

Agent 与 Edge Hub 按契约 C2 使用 gRPC（grpc-go、protobuf 运行时）与 SQLite。当前开发环境访问 Go 模块代理 `proxy.golang.org` 被网络策略拒绝（403）；已决定放行该代理（2026-11-01）；第二～九批开始时复查仍不可用（代理域名无法解析）。放行生效前先实现不依赖外部模块的部分：存储与传输抽象为接口，账本暂用 JSON 行文件（每次追加 fsync），放行后替换为 SQLite（WAL）与生成的 gRPC 代码，接口不变。

CI 首次运行发现一处计量丢失并已修正：进程退出时如果先做最后一次拉取再关闭引擎，关闭过程中结束的会话的最后字节不会进入计量。新增 `Agent.Shutdown`：先关闭引擎，再拉取、封批、落盘，下次启动时作为上次启动的批次最先上报；`vortex-node run` 与测试都改用它。初版模拟漏掉了“去掉 available 上限检查”（超发后 available 恰好为 0，守恒检查被跳过）：补上“每次签发后 issued + pending ≤ delegated”不变量后被发现。

端到端测试发现一处设计错误并已修正：Edge Hub 起初要求同一启动的计量批次序号连续，缺批不确认。但切换实例前已被原实例确认的批次不会重发，新实例看到的序号天然有缺口，导致之后的批次永远不被确认。改为按 (node, boot, seq) 逐个去重、不要求连续；累计确认仍成立，因为 Agent 在一条流上总是按序号递增发送全部未确认批次。

第七批的端到端测试又发现两处问题并已修正：① 节点切换实例后重启，新实例从未给它推送过份额（份额原先只在节点首次 Prepare 时由后端推送），租户限速为 0、无法转发。改为 Edge Hub 在节点接入时上报在线状态，后端据此为每个新启动推送份额。② 已上报条目全部被确认后，其后的本地专用条目永远显示为“未确认”。改为在这种情况下本地推进确认位置。

第八批的随机测试发现一处原有缺陷并已修正：节点首次接入时，签发器只在内存中记下它的启动 ID，没有写账本。如果之后还没签发任何授权 Edge Hub 就重启了，就认不出该节点的下一次新启动，LIM-010 转移会被漏掉。现在首次接入也写账本。
